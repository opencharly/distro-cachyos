# 2026.268.2305 — fix(tmp): restore /tmp 1777 in the nesting boxes via one shared candy (RCA)

## Summary

Restores `/tmp` to the distro-standard world-writable sticky mode (`1777`) in
the boxes that ship it broken, via **one shared candy** (`candy/tmp-sticky`), and
deletes the one duplicate inline copy.

### Root cause (RCA 2026-09-24)

A BuildKit **cache mount rooted under `/tmp`**
(`--mount=type=cache,...,dst=/tmp/...`) combined with a **nested container
runtime that writes under `/tmp` in the same RUN** makes BuildKit
**materialise `/tmp` as a fresh directory at the process umask (`0755`)** instead
of preserving the lower layer's `1777`. The change is committed into the image,
and every uid-1000 writer of `/tmp` then EACCES'd (supervisord's
`logfile=/tmp/supervisord.log`; pod-dbus's `unix:path=/tmp/dbus-session`).

`layer-container-nesting`'s pre-pull is exactly that combination (a heredoc
`podman pull` under a `dst=/tmp/npm-cache` cache mount), so every box composing
it shipped a broken `/tmp`.

**Proven in the failing build itself** — probes inserted around the two steps of
the emitted `charly-selftest` Containerfile:

```
STEP 37/107: RUN stat -c "PROBE-after-xdgmkdir /tmp=%a %U:%G" /tmp
PROBE-after-xdgmkdir /tmp=1777 root:root
STEP 71/107: RUN stat -c "PROBE-before-download /tmp=%a %U:%G" /tmp
PROBE-before-download /tmp=755 root:root      # <- container-nesting pre-pull ran between
STEP 71/107: ... cp -f "$__c" /tmp/claude-code-install.sh ...
cp: cannot create regular file '/tmp/claude-code-install.sh': Permission denied
```

Controlled 2×2 (base image, unmodified):

| variant | cache dst | nested runtime | image `/tmp` |
|---|---|---|---|
| base | — | — | **1777** |
| cache under `/tmp` | `/tmp/npm-cache` | no | **1777** |
| nested runtime, cache outside `/tmp` | `/var/cache/npm` | yes | **1777** |
| **both** | `/tmp/npm-cache` | yes | **755** |

Either factor alone is harmless; only the combination breaks it. **The host is
not affected** — rootless isolation holds; the `0755` lives in the image's own
overlay upper layer.

in this PR (not dismissed).** First run: `check-image` PASSES; `check-live`
reaches **129 steps, 108 passed, 1 failed, 20 skipped**, the one failure being:

```
FAIL check THE FULL LOCAL LOOP — scratch git workdir, lease via
     local-container, sync, run, stream, release (exit-2 acceptance)
     [cbx-e2e-loop]  execution error: process terminated by signal (signal: killed)
killed by the per-attempt never-hang bound of 2m0s — the step ran longer than
that, it did not crash.
```

**RCA:** that step leases a real nested container, syncs a git workdir and
streams a command — minutes of genuine work — but the step declared **no
`timeout:`**, so it fell back to the harness's never-hang default (120s,
`readinessPerAttemptFallback`; the message's `2m0s`). The harness was right to
kill it; the step's bound was simply wrong. The sibling long steps in `charly.yml`
already declare explicit bounds (`timeout: 5m`, `timeout: 600s`). **Fix in-tree:**
`cbx-e2e-loop` now declares `timeout: 10m` (`charly.yml`) — which also covers the
loop's own `--ttl 15m`/`--idle-timeout 5m` semantics, i.e. the bound is larger
than the work the step can legitimately do, not tuned to one observation.

**Proven under load, not on an idle re-run.** The failure surfaced while the
self-hosted runner reviewed a PR on the same host. The fix was re-verified
**while the `check-openclaw-desktop-pod` bed was building concurrently** (same
contention class), with the bound in place — a full 14/14 PASS:
