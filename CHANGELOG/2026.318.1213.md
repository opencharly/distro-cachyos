# 2026.318.1213 — feat(bed): prove the plugin round-trip in check-openwebui-pod

## Summary

`check-openwebui-pod` — the bed that owns the openwebui image — now also proves the `charly openwebui`
plugin against the server it just started, in the three-step shape the ledger asked for. Head
`1ccd5e9d98793907eac750d13382335c923e13eb` (branch updated onto current `main`), **1 file, +99**:
`charly.yml` only — one project `import:` entry and three plan steps. No box, image, candy or deploy
definition changes; the earlier version of this branch appeared to touch `box/openwebui/charly.yml`
because it was cut from the pre-squash `main` of opencharly/distro-cachyos#164, and
`gh pr update-branch` collapsed that to the real diff.

| Step id | What it asserts | Why it can fail |
|---|---|---|
| `openwebui-plugin-absent` | the entity declares `models.DEFAULT_MODELS: bed-drift-proof`, which the server does not have, so `charly openwebui diff` exits **non-zero** and names the `models` surface | fails if the server already holds the value (the round-trip would prove nothing) or if `diff` reports drift without naming the surface |
| `openwebui-plugin-change` | `apply` posts the surface in one call, and the `diff` that follows is **clean** | fails if `apply` errors or if the next `diff` still sees drift |
| `openwebui-plugin-present` | a `save` **READ-BACK** from the server carries `DEFAULT_MODELS: bed-drift-proof` | fails if the read-back does not carry the value — what separates "we posted it" from "the server has it" |

Two mechanics make it work without weakening anything:

- **`import: owuicli: '@github.com/opencharly/plugin-openwebui:v2026.317.2055'`** — an IMPORT, not a
  composition. The command word registers from the imported repo's own discover tree (the fix that
  landed as charly#1136), so no image gains the plugin binary and the bed still runs the real CLI.
- **The credential is the deployment's OWN generated secret**, read with
  `charly secrets get charly/secret WEBUI_ADMIN_PASSWORD` into a shell variable. It is never echoed and
  never written to disk: the entity carries `auth.email` and no password at all, and the read-back file
  is a bare `repo:` plus whatever `save` writes. No new bed credential contract, no store pollution, no
  skip.
