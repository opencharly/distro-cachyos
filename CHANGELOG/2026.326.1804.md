# 2026.326.1804 — feat(boxes)!: aur is a routed builder in this repo's boxes, and the imports move to the releases that agree

## Summary

`aur` stops being a box `build:` format and becomes a routed builder everywhere in this repo, and the two namespaces it imports move to the releases that agree with that (opencharly/sdk#608). This is the `distro-cachyos` half of the cutover.

- **`aur` leaves every `build:` list** — `charly-selftest`, `selkies-kde`, `selkies-kde-nvidia-cdi`, `selkies-labwc`, `selkies-labwc-nvidia-cdi`. `build:` names OS package formats only; an AUR package reaches an image because a composed candy declares `distro.<tag>.aur` and the build routes the `aur` builder to a builder box.
- **The route is declared where it was missing.** `box/nvidia-cdi` declared no `builder:` map, and the two selkies CDI boxes declare only `pixi` — so with the opt-in gone they had no AUR route at all. The route is now declared ONCE on that shared base, inherited by every box that bases on it, exactly as `box/cachyos` declares it.
- **`arch:` `v2026.325.1112` → `v2026.326.1455`** (distro-arch#77), the release where `aur` is a routed builder.
- **`podcdi:` → `v2026.326.1530`** (pod-cdi#13, merged `952c2f6`), built on that same distro-arch generation.
- **A permanent witness**: `candy/aur-probe`, `box/aur-probe` and the disposable bed `check-aur-probe-pod`. The box composes one candy that declares one AUR package; it declares no `builder:` map of its own and no `aur` in its `build:` list, so its build can only succeed if the base's map routes the declaration AND the builder's reply carries the package.
- The five skills and two box comments that described the old silent drop as expected behaviour now describe the mechanism.
