# 2026.243.0737 — fix(bed): pin the cstream verb plugin so the bed parses when composed

## Summary
check-cstream-pod authors the cstream verb's SCALAR shorthand:

    cstream: status

That desugars at PARSE time, before any out-of-process provider can connect, from the primary
charly's prescan registers off a plugin candy manifest's plugin.primary block. The prescan can
only read a manifest it can REACH - one pinned from a file it walks. This bed pinned nothing,
so the verb was reachable only where this file IS the root file.

The result was an asymmetry that reads as a broken bed when the bed is fine:

    charly box validate   (from this repo root)          exit 0
    charly box validate   (from charly, composed)        exit 1

    parse: node "check-cstream-pod": plan[29] plugin verb "cstream" takes a MAP input
    (it declares no primary field for the scalar shorthand)

charly composes this repo as box/cachyos, so this took charly box validate on charly's OWN main
to exit 1 - a red main for every session, from a bed that passes its own gate.

Pinning the plugin the bed's steps actually use is the same thing distro-arch does for
plugin-spice and distro-omarchy for plugin-wl, and it is what makes the shorthand reachable
wherever this file is read.

## The other half

A pin here is necessary but not sufficient: charly's parse-time prescan walked the root file
and its discover: paths and NOT its import: namespaces, so an imported box's pins were never
read at all. That is fixed in opencharly/charly#508 (the import leg). Verified together on the
composed tree - neither half alone clears it:

    import leg only,      no pin here     exit 1
    pin here only,        no import leg   exit 1
    both                                  exit 0

## How tested

    charly box validate
    [exit 0]

The composed proof is the one that matters, and it is in charly#508: with this pin present in
box/cachyos and the import leg applied, charly box validate at charly's root goes 1 -> 0.
