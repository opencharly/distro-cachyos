## Summary

Phase-4 candy de-submodule cutover sweep: the moved candies no longer resolve from
`@github.com/opencharly/charly/candy/<name>` (the in-repo candy/ dirs are deleted on
charly main). This PR advances every stale `charly/candy/<name>:v<old>` ref in this
repo to the candy's STANDALONE repo at its own CalVer tag:

- `layer-*` / `pod-*` candies → bare `@github.com/opencharly/<kind>-<name>:v<tag>`
- `plugin-*` candies → `@github.com/opencharly/<plugin>/candy/<plugin>:v<tag>` (the
  module-subdir shape the compiled plugin convention uses)
- the in-repo candies that legitimately stay (this repo keeps exactly 2 of charly's
  14 in-repo meta-candies: `charly`, `charly-mcp`) remain as `charly/candy/` refs

The sweep is mechanical (one canonical replacement table derived from the org's repo
list + each standalone repo's latest tag) and was applied by
`/tmp/sweep-box-repo.py` (regex on the full ref + old-tag suffix).
