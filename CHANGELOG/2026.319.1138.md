# 2026.319.1138 — feat(qwen3-tts): add the speech-service image and its disposable bed on the CachyOS base

## Summary

Adds the **Qwen3-TTS provider** to this repo's images, on the CachyOS base:

- **`box/qwen3-tts`** — the composed image: `base: cachyos`, pinning
  `@github.com/opencharly/pod-qwen3-tts:v2026.319.1119` (the release that made the candy's C toolchain
  package list distro-aware, so Arch installs `gcc` while Fedora keeps `gcc` + `gcc-c++`). No CUDA layer
  is composed: torch's cu130 wheels carry their own CUDA runtime and the driver arrives through CDI at
  runtime.
- **`check-qwen3-tts-pod`** — the disposable bed, and the only thing that proves the composed image
  satisfies the contract Open WebUI's `openai` TTS engine calls: `/health`, `/v1/audio/voices` (the
  preset list a consumer's picker reads), and a `POST /v1/audio/speech` asserted on the **RIFF magic byte
  in the response body** plus an `audio/*` content type, so an empty `200` cannot pass. The first
  synthesis downloads the 0.6B checkpoint into the pod's models volume, so every probe is
  readiness-bounded (`eventually`), never a fixed sleep.

Operator direction: the provider image runs on **CachyOS**, not Fedora — that is why this box lives in
this repo and not in `distro-fedora`.
