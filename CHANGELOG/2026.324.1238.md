# 2026.324.1238 — feat(immich)!: one `immich-cdi` image on the CachyOS GPU base; drop the separate ML image

## Summary

**One `immich-cdi` image for the whole Immich stack on the CachyOS GPU base, replacing the separate `immich-ml-cdi` box and its bed.**

The producer is `opencharly/pod-immich#13` (merged 2026-11-16): Immich v3.4.1 carries the server, the web UI and the machine-learning backend (port `3003`) in ONE candy, in ONE image. This leg adopts that: it adds `box/immich-cdi` on the `nvidia-cdi` GPU base, deletes `box/immich-ml-cdi`, and renames the bed `check-cachyos-immich-ml-pod` to `check-cachyos-immich-pod` (image `immich-cdi`).

Five files, 29 insertions / 27 deletions:

- `box/immich-cdi/charly.yml` — new: `base: nvidia-cdi`, `build: [pac]`, and the candy set the one-image stack needs (`agent-forwarding`, `nodejs`, `supervisord`, `pod-postgresql`, `layer-vectorchord`, `pod-redis`, `pod-immich`, `pod-dbus`). `pgvector` ships in Arch `extra`, so no AUR stage.
- `box/immich-ml-cdi/charly.yml` — deleted.
- `charly.yml` — the bed is renamed and re-pointed at the new image, with a description that states the three services (`immich-db-init` oneshot, `immich-server` on 2283, `immich-ml` on 3003) and why `requires_shared: [nvidia-gpu]` stays.
- `.agents/skills/cachyos/SKILL.md`, `README.md` — the box lists name `immich-cdi` instead of `immich-ml`.

**The pin is `pod-immich:v2026.324.1202`, and that number is the story of this PR.** The preserved work pinned `v2026.320.0058`. Composing it and running this very bed surfaced two PRODUCER defects, each fixed at its source before this leg could honestly land:

1. `v2026.320.0058` exported its pnpm pin as an un-namespaced `var: PNPM_VERSION`. `var:` values become image ENV, so it shadowed `layer-nodejs`'s identically named pin and `layer-nodejs`'s own measurement check failed at `check-image` (one check of 123: `pnpm 12.15.0 is UNMEASURED`). Fixed by `pod-immich#16` → `v2026.324.0914`.
2. On that tag `check-image` went green and `check-live` went RED: the one-image server dialed TCP `127.0.0.1:5432` while the composed `pod-postgresql` starts its cluster with `-c listen_addresses=''` — socket-only, no TCP listener at all — so `immich-server` crash-looped on `ECONNREFUSED` and `/api/server/ping` reset. Fixed by `pod-immich#18` → `v2026.324.1202` (the server dials the unix socket; two image-check assertions make the regression red instead of a crash-loop).

Both defects were measured in THIS bed, filed with the container journal, and fixed producer-first; this leg is the consumer adoption of the result. The `pod-postgresql` half — its description promises TCP `127.0.0.1:5432` while its entrypoint disables it — is filed as `pod-postgresql#5` and is not this repo's to change.
