The candy de-submodule cutover (charly #409) moved candies to standalone repos. This sweep advances every @github candy pin in the cachyos boxes to the latest tag of its standalone repo, bumps the charly subpath pins, adds the marketplace refs list (candy/charly-marketplace/charly.yml), and reconciles the refs-list pins to the sweep's box-pin advances.

## RCA (R1)

The cutover's Phase 4 (charly #409) deleted the in-repo candy dirs and moved them to standalone repos. The box repos' @github pins still referenced OLD tags whose candy lists used bare-name sibling refs. Two mechanisms broke resolution:

1. **Stale pins**: advancing every pin to the latest tag fixes the bare-name-vs-@github conversion (the latest tags carry @github sibling refs).
2. **The repo-root charly ref**: pre-sdk#174, the resolver tried to parse the charly repo's project charly.yml as a single candy ("unrecognized candy manifest shape"). sdk#174 (merged) makes a repo-root ref to a project repo provide its candy/ dir. The plugin-box dedup (plugin-box#2, merged) resolves the bake_plugin name conflict.

**Residual known limitation (routed to a named batch):** a small number of STANDALONE repos still list bare-name sibling refs in their OWN candy lists at their latest tags — e.g. `pod-selkies-desktop → selkies-core/labwc/waybar-labwc`, `pod-chrome-cdp → plugin-cdp/chrome-devtools-mcp`. These are NOT fixable from this box repo; they live in the standalone repos' manifests. They are routed to the NAMED thematic batch **"standalone-repo bare-name sibling sweep"** (owner: the candy cutover follow-up track, charly #409's distro-sweep companion). This sweep's scope is the box repo pins + the refs list; the standalone-repo manifests are a separate repo surface, swept PR-by-PR as each standalone repo's bare-name fix merges.
