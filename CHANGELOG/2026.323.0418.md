## Change classification

Every `*-cdi` pod box in this repo inherits a base that no longer composes a driver layer. The
change is deliberately breaking for a pod image: a CDI pod must bake no driver user-space, and
until this tree its toolkit dependency silently put one back. The five VM-side `layer-nvidia` pins
are **unchanged** in this diff: those boxes compose `layer-nvidia` themselves, and their bump to
the anchored-strip release is opencharly/distro-cachyos#210, gated on the VM bed that would execute
it.

**Breaking change + rollback:** `box/nvidia-cdi` and `box/versa` change base and lose the baked
driver, and `box/comfyui-cdi` (through `nvidia-cdi`) loses it too — so a consumer that relied on an
image-baked driver inside a CDI pod breaks by design; a passthrough guest is served by
`opencharly/vm-nvidia`, which composes `layer-nvidia` itself. The bed's steps also change shape
(three defects removed, `sh:` replaced with documented verbs), so anything that parsed this repo's
bed output sees different step prose and ids are unchanged. `box/versa` still composes
`layer-nvidia` on **two independent chains**: its base (`pod-cdi v2026.322.1717` → `layer-cdi
v2026.322.1100` → `layer-cuda v2026.321.1520` → `layer-nvidia v2026.320.1938`, filed as
opencharly/pod-cdi#5), and `pod-marimo v2026.320.2210` → `layer-cuda v2026.320.2103` →
`layer-nvidia v2026.320.1938`, with `pod-airflow` reaching the same toolkit through `pod-marimo`
(filed as opencharly/pod-marimo#12). Neither is fixable from this repo, and `box/versa` is
independently unbuildable (opencharly/distro-cachyos#203), so this PR does not claim versa is a
clean pod. Rollback restores
`base: cachyos` with `layer-nvidia` + `layer-cdi` + `layer-cuda`, the previous `pod-comfyui` and
`layer-cdi` / `layer-cuda` tags, and the prior bed body.
