## The SHA exception, named

`layer-nvidia` is pinned by **raw SHA** in all six sites while every sibling ref is a tag. That is deliberate and it has a concrete cause, not a stylistic one:

`layer-cuda` pins `layer-nvidia` **by SHA**, and this resolver counts a SHA ref and a tag ref of the *same commit* as a multi-version disagreement:

```
box/nvidia  layer-nvidia:v2026.289.1705                            -> validate FAILS
            candy layer-nvidia resolved to multiple git tags with differing content
box/nvidia  layer-nvidia:054aa7702ebe79e8be444764f91a03933ba45eec -> validate OK
            (the same commit)                                      425 candies, 0 warnings
```

So the pin uses the **form the transitive producer already uses**, and only the commit moves. Recorded as the fourth defect in **`opencharly/charly#974`**, with the measured experiment above.
