# 2026.332.0718 — feat(check): a bed that renders an imported box, so the import-back-edge class stays covered

## Summary

`opencharly/distro-cachyos#270`, closing the coverage gap `opencharly/charly#1295` exposed: **this project
imports owner repos and can address their boxes by namespace, but nothing here ever RENDERED an imported
box.** Every bed built this project's own.

**Why it matters.** Until `opencharly/sdk#654`, a box reached through an import lost the import **back-edge**
its `base:` names — `pod-whisper`'s `whisper` declares `base: cachyos.cachyos`, and `cachyos` is the very
project that imports `pod-whisper`. The reference dangled, and the failure surfaced two stages later as
`build: field required`, then `DistroDef == nil`.

**The bed.** The check is a HOST render — `charly box generate pod-whisper.whisper` writes
`.build/pod-whisper.whisper/Containerfile` without building or running anything — so the bed needs no venue:

```yaml
check-cachyos-imported-box-render:
    local:
        from: cachyos-render-host-template
        host: local
        disposable: true
        lifecycle: test
```

and its one step asserts three things about the emitted artefact, in the order they can fail:

1. the Containerfile exists (the render resolved the imported box at all);
2. it carries a `FROM` (a real image was produced);
3. the base resolved — `BASE_IMAGE` is present, which is exactly what a dangling `base:` does not set.
