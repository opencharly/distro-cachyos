# 2026.279.0046 — fix(box): advance pod-github-runner to v2026.279.0028 — deliver the runner-image tool fixes to the fleet

## Summary

Closes #122. One line in `box/githubrunner/charly.yml`:

```diff
-            - '@github.com/opencharly/pod-github-runner:v2026.274.0625'
+            - '@github.com/opencharly/pod-github-runner:v2026.279.0028'
```

This is the second link of the chain that puts `pod-github-runner#8` on the fleet. That PR
(merged `297c9eae7f514e2978d41d2aabdb4e6e7b9bb3ce`, tag `v2026.279.0028`) fixed three defects in
the image the org's self-hosted CI jobs execute in: the missing `hostname(1)` that fails
charly's own venue test on the pool, 24 further packages every CI job reaches for, and a dead
`RUNNER_GROUP` knob. The tag exists; until this pin moves, the fleet keeps resolving the old
bytes and none of it ships.

### What the old pin was costing

Verbatim from the `go` check-run of `charly#807`
([job 111961186574](https://github.com/opencharly/charly/actions/runs/37369026337/job/111961186574)),
440 s — well inside the required check's 600 s budget, so a real failure, not a duration stall:

```
--- FAIL: TestInvokeProvider_VenueDescriptor_Venueless_ShellDescriptor (0.97s)
    plugin_dispatch_reverse_venue_test.go:155: venue-less + shell descriptor peer result: {Status:pass Message:peer-executed Stdout: Stderr:bash: line 1: hostname: command not found
         Exit:127}
    plugin_dispatch_reverse_venue_test.go:161: peer executed on the WRONG host: got "" want "charly-githubrunner-no-2" (host-local materialization failed)
```

The runner image carried Arch's `coreutils`, which ships no `hostname(1)` — it lives in
`inetutils`. charly's venue descriptor shells out to `hostname` to prove a peer ran
host-locally, so the test fails **for the image**, and every repo whose CI runs `go test ./...`
on the pool inherits the red.

### Why this is the whole change

The composition is otherwise untouched: the other five pins in the box
(`layer-agent-forwarding`, `layer-charly`, `layer-gh`, `pod-dbus`,
`layer-container-nesting`) are deliberately left alone. Advancing them is #41's whole-tree-sync
question, is not needed to deliver this fix, and #48 measured that advancing pins here does not
come for free. Per this repo's own `AGENTS.md`, the embedded `githubrunner` skill entity moves
with the box manifest — and it needs no edit here, because it names no pin: the layer list is
`agent-forwarding, github-runner, charly, dbus, container-nesting`, unversioned.
