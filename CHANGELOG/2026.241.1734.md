# 2026.241.1734 — docs: the charly-marketplace copy is a candy closure, not the generation source

## Summary of changes

`candy/charly-marketplace/charly.yml` in this repo carries a description **copied verbatim from
`opencharly/marketplace`**. It says the file is:

> The marketplace corpus SOURCE — the candy-dir charly.yml that makes
> `charly marketplace generate --root <this repo>` work post-cutover.

In a distro repo that is simply **false**. Nothing here generates the marketplace, and this file
declares no `marketplace:` entity at all.

**What it actually is:** the shared candy **closure** this repo resolves against — one `candy:` list
naming every standalone candy repo whose entities the images here need, so a bare reference like
`kde-shell` resolves without each box pinning it individually.

## The false description invites two opposite mistakes — and the cutover plan made the second

| Mistake | Why it's wrong |
|---|---|
| Keeping this file byte-equal to the marketplace repo's list | They answer **different questions** — what *this repo's images* need, versus what the *published corpus* is generated from. They have already diverged in both directions: **178 / 168 / 177** refs across cachyos, fedora and marketplace. |
| Deleting it as a redundant mirror | **The cutover plan (C.4) called for exactly this.** Measured before acting: removing it makes `charly box validate` fail here. |

```
$ rm -rf candy/charly-marketplace && charly box validate
charly: error: command "validate": 5 validation errors:
  candy "kde-selkies" depends: unknown candy "kde-shell"
  candy "github.com/opencharly/pod-kde-selkies" depends: unknown candy "kde-shell"
  global candy order: resolving candies for image "selkies-kde": unknown candy "kde-shell"
  …
```

The closure is load-bearing. The plan's premise — that these are redundant divergent mirrors — does
not survive contact with the repo.

The plan also warned they *"avoid a 'more than one marketplace entity' hard error only because they
happen to agree on one pin"*. They declare **no** `marketplace:` entity, so that hazard does not
exist either:

```
$ grep -c '^\s*marketplace:' candy/charly-marketplace/charly.yml
0
```
