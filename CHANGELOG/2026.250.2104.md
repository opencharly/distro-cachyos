# 2026.250.2104 — fix(check): the check-android-emulator-pod adb session lifecycle — ONE threaded session (E-4)

## Summary

The E-4 android lane's check-android-emulator-pod fixture ran TWO parallel adb screen-record sessions: the plugin-adb ADE plan's own lifecycle (adb-session-start → adb-session-status → adb-session-stop, session id `ade-adb-session`) AND a fixture-level `instrument:` block (`id: screen`, which the runner addresses as session id `check-android-emulator-pod.screen` with a run-scoped capture dir). The `adb-session-stop` ADE gate polls the ADE identity's evidence row — `/tmp/charly-session/ade-adb-session/row.json` — while the recorder that reliably finalizes is the instrument's. The full-mode run (calver 2026.250.1940, 299 PASS / 2 FAIL / 23 SKIP, single real red) failed exactly there:

    FAIL [adb-session-stop]  adb: session: exit=1, want 0
      stderr: "/tmp/charly-session/ade-adb-session/row.json": evidence row missing after 20s (recorder never finalized)

while the E-4 instrument's own recorder.log proves a clean finalize under the OTHER session id:

    charly-adb recorder: finalized session check-android-emulator-pod.screen bytes=84694294
      state_dir=.check/check-android-emulator-pod/2026.250.1940/capture/check-android-emulator-pod.screen

**RCA (the session-identity mismatch):** the stop gate polled a path no recorder writes. The fixture's parallel instrument recorder was unreachable from the statically-authored ADE lifecycle (its identity is runner-injected + run-calver-scoped at authoring time — `state_dir` cannot be threaded into a plan step), and the ADE's own second recorder cannot produce on the device: the emulator's screenrecord encoder is already owned by the instrument's capture, so it dies against the runner's TERM→KILL grace without finalizing.

**The fix — ONE threaded session (consistent with the E-1/E-3 fixtures):** the plugin ADE plan is the bed's SINGLE adb session lifecycle. The fixture declares no parallel adb screen instrument (the lane working fixture carried a plugin-media pipeline candy for it; the landed fixture includes only the plugin-adb serving candy — nothing to remove, nothing unused), and the ADE plan's start/status/stop thread one session id (`ade-adb-session`) through one recorder — the stop gate's poll path IS the recorder's evidence path by construction. The `status-shows-nested` assertion is also corrected to the honest device-row surface (the android devices are deploy-level members; the `nested[]` overlay does not nest them — the fixture's checked-in form, proven green at 1940).

The change is confined to the check-android-emulator-pod bed block (one file, +26/−8); no other bed is touched.
