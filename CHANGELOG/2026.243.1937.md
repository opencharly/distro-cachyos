# 2026.243.1937 — feat(punktfunk): make the fleet bed prove streaming, and fix what stopped it

## Summary

Phase 1 shipped punktfunk beds that could not fail for the reason that matters. They proved
installation and the control plane — packages land from the signed repo, the daemon reaches
`serve`, the management API answers, the packaged user unit is active — and **not one of them
proved punktfunk streams**. Both were single-node. The evidence was in the green output itself:

```
PASS  check the verb lists paired native clients (empty on a fresh host, but authenticated)
      [pf-verb-clients]  []
```

No client had ever paired, no session on `9777/udp` had ever opened, no frame had ever been
encoded. Everything shipped would still have passed if punktfunk could not stream at all.

This PR adds a **two-member fleet bed** that pairs a real client to a real host and asserts a
frame was actually delivered, plus a client-side bed for the `punktfunk` CLI surface.

## What each assertion catches

- a host that installs but never listens on `9777/udp` — pairing fails, exit `2`
- a broken trust store — pairing fails, exit `3` (reported as *trust rejected*, not a shrug)
- an encoder that cannot start — the stream assertion fails, exit `4`
- a host that accepts pairing but never emits a session — no `streamed:` line

None of those is detectable by anything Phase 1 shipped.

## The warnings this PR used to carry, and what it took to clear them

Earlier revisions of this PR reported `2 warnings, 0 errors` and argued at length that 2 was the
floor. **That was a true measurement and the wrong conclusion, and the reviewer was right to
block it four times.**

The root cause was never in this repo. The `layer-xdg-portal` entity the closure resolved
(`2026.144.1443`) declares `distro:` with only `fedora:` — no `arch:` — so on a CachyOS base it
installs nothing and then fails its own checks. This bed is the repo's first arch consumer, so it
had to pull the arch-capable entity, and a second entity version was the unavoidable arithmetic.
`origin/main` read 0 warnings not because it was current but because it was uniformly **old**.

Reaching zero required repairing the org's published tags, since a tag freezes its pins at mint
time and no edit here can rewrite a pin inside someone else's tag:

```
13 waves, 36 PRs merged across 20 repos, leaves-first, closure re-measured between waves
12 conflicting candies -> 0
```

then landing the consumer side as its own change (**#58**, 204 pin lines, kept out of this PR so
a repo-wide repair is not hidden inside a feature branch). This PR now sits on that main and
inherits a clean closure.

Three things were measured and rejected along the way rather than argued away: aligning the boxes
*down* to the fedora-only entity reaches `0 warnings` and produces a bed that **fails** at
`check-image` with three missing packages; advancing every in-tree ref mid-campaign gave 12
conflicts; a partial advance gave 26.
