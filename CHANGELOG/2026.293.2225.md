# 2026.293.2225 — feat(openwebui): the box on the refreshed CachyOS base, with a disposable witness

## Summary

The Open Web UI image now builds from the CachyOS family on a **current** base. Two parts:

**1. The CachyOS base pin was stale and is refreshed.** `box/cachyos` pins
`docker.io/cachyos/cachyos-v3` by digest (Docker Hub publishes only a rolling tag for that
repo, so a digest is the only precise coordinate), and that digest had drifted from upstream —
every image this family built was an older snapshot:

```
pinned before:  sha256:7ada9fc1c311c2f651f62ab75b6b95f4b341a51eba3f9b6d133eb12b370bedb0
pinned now:     sha256:f50fa29540b3de01845f908202c91e4cddc7d1cdaac1b25ad33332afba94184b
```

Measured with an anonymous registry token against `:latest` (`Docker-Content-Digest`) — the
skopeo-less form of the refresh recipe the box's own comment documents.

**2. `box/openwebui` is new here** — the same candy composition as
`distro-fedora/box/openwebui`, on `base: cachyos`:

```yaml
openwebui:
    candy:
        base: cachyos
        platform: [linux/amd64]
        candy:
            - '@github.com/opencharly/layer-agent-forwarding:v2026.274.0608'
            - '@github.com/opencharly/pod-openwebui:v2026.293.1944'
            - '@github.com/opencharly/pod-dbus:v2026.274.0648'
```

Same three candies as the Fedora box, so the two images differ only by base distro and stay
comparable. It ships with the disposable bed `check-openwebui-pod`, carrying **two**
assertions the composition cannot fake: the served open-webui version, read from the app's own
`/api/config`, and the **base identity**, read from `/etc/os-release`.

### The base assertion can fail on this change — measured, not asserted

A base **digest** never reaches the guest, so the only runtime witness that the image came from
the pinned base is the base's own `/etc/os-release`; `VERSION_ID` is the digest's fingerprint.
The two digests are measurably different, which is what makes the new check a real gate rather
than a tautology:

```
old pinned digest 7ada9fc1…bedb0  →  ID=cachyos  VERSION_ID=20261011.0.609700
refreshed digest  f50fa295…4184b  →  ID=cachyos  VERSION_ID=20261018.0.612668
```

(The first line is read from the old base image still present in the local store; the second
from the image under test.) So the bed would have **failed on the stale base**, and the
`check-live-rebuild` leg proves the assertion survives a destroy-and-rebuild.

When the digest advances, this line advances with it in the same change — the box owns the pin,
so the box owns the expectation. That is the same coupling the served-version check uses, and
the one whose absence let the Fedora box ship a three-release-old candy
(opencharly/distro-fedora#102).

do not share one:
