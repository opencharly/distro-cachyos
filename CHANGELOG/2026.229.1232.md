# 2026.229.1232 — CachyOS ollama takes the packaged install, and gains an AMD sibling

CachyOS is a packaging distro for ollama, so the images built here stop downloading the
1.32 GiB upstream tarball download and start installing the 66 MiB `extra/ollama` package
(`0.32.14-1`, which tracks upstream closely — it landed the day upstream tagged
`v0.32.14`). The change itself is in the shared `ollama` candy; what lands here is the
composition that takes advantage of it.

## `ollama` — the CUDA backend is composed explicitly

The tarball bundled every GPU backend, which is most of its size. The Arch packages
split them, and `ollama-cuda` DEPENDS on `ollama` rather than conflicting with it, so
the GPU box composes the backend as its own candy:

- `box/ollama` (on the `nvidia` base) adds `ollama-cuda` — ~988 MiB, only here.
- `box/openclaw-desktop` composes the plain `ollama` candy and now pays 66 MiB for its
  CPU ollama where it previously downloaded a 1.32 GiB archive. Its bed description said the image
  builds an "ollama tarball multistage"; it does not any more, and now says so.

`check-cachyos-ollama-pod` gains no `plan:` of its own — the server probes, the CUDA
backend probe, and the three host-side `charly ollama` steps all arrive baked into the
candies it composes.

## `ollama-rocm` — a new AMD box and its bed

`box/ollama-rocm` is the AMD sibling of `box/ollama`: the plain `cachyos` base
(deliberately NOT `nvidia`), plus `ollama` and the new `ollama-rocm` backend candy. No
`rocm` candy is involved — the `ollama-rocm` package bundles its own HIP/HSA runtime
(`libamdhip64`, `libhsa-runtime64`, `libhipblas`). At ~2.9 GiB installed it is by far
the largest backend, which is exactly why it is opt-in and why nothing else composes it.

`check-cachyos-ollama-rocm-pod` is its disposable bed, and the sole consumer that
proves the `ollama-rocm` candy at all. Its scope boundary is stated in the config
rather than left to be assumed: on a host with no AMD card passed through, the bed
proves that the image composes, that the ROCm backend library really ships, and that
the server reaches steady state — NOT that inference runs on an AMD GPU. Ollama falls
back to CPU there, which is why every inherited runtime check still passes. Live GPU
enumeration needs a real card, the same limit `candy/rocm` states for itself.

Because the box sits on the plain CachyOS base, the bed doubles as the proof that the
`ollama` candy composes with no GPU candy at all.
