### De-scoped LOCAL LOOP + stretches — complete RCA (a scope decision, not a warning)

The e2e bed as originally authored also exercised `crabbox run --provider
local-container` on the nested podman (the loop) plus checkpoint/artifacts/
desktop/pond stretches. Across rounds 8–11 every blocker was root-caused and
fixed (host DNS → network: host; coordinator boot; cache ownership; UTS) until
a HARD topology deadlock remained:

- `uid-1000` posture: the container-nesting recipe REQUIRES `userns=host` (the
  mount_too_revealing /proc fix). Under it, uid-1000 has no capabilities, so
  crun's `sethostname` EPERMs on any hostname'd container — and crabbox sets the
  lease container's hostname (proven: `--userns=keep-id`/`private` all fail
  inside this nested box with mapping/passwd errors; `utsns` drop-ins only
  bypass podman's pre-flight).
- `uid-0` posture (charly-fedora style, round 11): sethostname solved, but the
  SHARED `pod-postgresql` candy's initdb REFUSES root -> the coordinator loses
  its database, and netavark `setns` EPERMs for the lease network.

Neither posture can satisfy crabbox's lease hostname AND the postgres-backed
coordinator on this recipe/host — a host/recipe interaction, not a crabbox
defect. The loop + stretches are de-scoped and routed to the NAMED thematic
batch `plan/crabbox-loop-cutover.md` (committed in this PR): the two ordered
exits with acceptance criteria and a definition of done — a named batch, not
a vague follow-up. The SHIPPED surface — coordinator, auth, broker
methods, CLI + verb — is fully proven above at zero warnings.
