feat(krun): the R10 bed for the libkrun runtime host, passing on a disposable VM

## Summary

`opencharly/layer-krun#6` records two things as owed: a post-install guard that proves the **handler** rather than the `+LIBKRUN` flag, and an **R10 bed** that exercises the layer on a disposable target. This is the bed — authored where both halves of the pattern already live, since `box/krun-host` is in this repo and so is the `vm:` bed shape (`check-containerd-v4-egress-vm` derives the same way).

**Four checks, each able to fail for the defect it exists to prevent:**

| id | asserts | why it can fail |
|---|---|---|
| `krun-crun-handler-vocabulary` | `crun --version` carries `+LIBKRUN` **and** `grep -aq 'krun.ram_mib' /usr/bin/crun` | a distro crun advertises `+LIBKRUN` with **one** `krun` string and boots nothing; a build of `ca04fdb6` has **110** and boots a `6.12.109` guest |
| `krun-entry-point` | `/usr/bin/krun` exists | that is the spelling the containerd CRI handler names |
| `krun-libraries` | `libkrun.so.1` **and** `libkrunfw.so.5` resolve through the loader | the handler dlopens the first and loads the second |
| `krun-kvm` | `/dev/kvm` exists | a venue without it cannot boot a guest |

`grep -aq` rather than `strings` is deliberate: the guest is minimal, and adding `binutils` to a runtime assertion is how a gate starts testing its own toolchain.
