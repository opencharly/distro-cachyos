# 2026.318.0951 — chore(pins): advance krun-host to layer-containerd v2026.318.0946

## Summary

`box/krun-host` advances its `layer-containerd` ref from `v2026.314.0705` to **`v2026.318.0946`**,
one line, because that tag split the rootful builder out of the candy
(opencharly/layer-containerd#10): `buildkit` is now its own host-oriented candy, so
`layer-containerd` carries `containerd` alone — declared in BOTH forms, `exec` for supervisord and
`use_packaged` for systemd — and has no packaged-only service left.

That removes the warning this project printed on **every** validate and **every** bed run:

```
Warning: box "krun-host" includes candy ".../layer-containerd" with a packaged-only service
(no custom-exec sibling), but composition does not preserve_user (its systemd unit will be ignored)
```

`krun-host` is the only composition of that candy in the org and it needs no builder, so nothing is
added to the box: only the ref advances.

## How tested

**The proof is the absence itself, counted rather than summarised.** `box validate` reports
`0 warnings` either way — it printed the warning while still summarising zero — so the check is the
raw `Warning:` count in the output:

```
$ charly -C <this worktree> box validate > log 2>&1; grep -c "Warning:" log
0
$ tail -1 log
charly box validate: OK — checked 461 candies, 40 boxes, 43 deploys, 7 distros, 7 builders; 0 warnings, 0 errors
```

The same command on `main` today (before this pin) prints that warning once. This repo has no bed for
`krun-host`; the candy's own behaviour is proven by its VM witness in
`opencharly/layer-containerd#10`, where the guest still reports `buildkit.service` enabled AND active
with the builder coming from the new candy.
