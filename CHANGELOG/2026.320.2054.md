# 2026.320.2054 — chore(ollama): advance the CachyOS ollama pins to the v0.40.16 cutover

## Summary

Producer-first advance of the two CachyOS ollama boxes onto the ollama v0.40.16 cutover.
`pod-ollama` v2026.320.1029 carries v0.40.16, and both backend layers that `require:` it are
tagged (`layer-ollama-cuda` v2026.320.1042, `layer-ollama-rocm` v2026.320.1237), so the
consumer pins move together:

```
box/ollama:      pod-ollama v2026.274.0620 -> v2026.320.1029
                 layer-ollama-cuda v2026.274.0847 -> v2026.320.1042
box/ollama-rocm: pod-ollama v2026.274.0620 -> v2026.320.1029
                 layer-ollama-rocm v2026.274.0751 -> v2026.320.1237
```

**Scope, stated plainly.** This PR advances the ollama pins ONLY. It deliberately does not
touch `box/nvidia`'s `layer-nvidia`/`layer-cuda` pins, even though this session also landed the
CDI driver-shadowing fix (opencharly/layer-nvidia#22, opencharly/layer-cuda#19) that the
CachyOS GPU images need. Reason, measured: advancing those here deadlocks this project's own
gate — `layer-strata` does `require: distro-cachyos:v2026.290.2137`, and that snapshot (an
earlier release of THIS project) pins the old `layer-nvidia` commit, so the box scope resolves
`layer-nvidia` at two refs and `charly box validate` hard-errors:

```
charly: error: command "validate": validation error: candy
github.com/opencharly/layer-nvidia resolved to multiple git tags with differing content
within one scope (box=versa); using newest referenced 7766a9d06ec5fe8c276c091a68fb72cea12688e3
```

No edit inside this repo can break that cycle (the required snapshot must first contain the new
pin, which needs the gate this error blocks). Filed as opencharly/distro-cachyos#184 with the
full RCA and the root-fix candidates; the GPU fix's consumer advance stays tracked there and in
opencharly/layer-nvidia#20. Splitting it out keeps the ollama cutover landable NOW instead of
hostage to a cross-project pin cycle.
