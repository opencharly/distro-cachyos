# 2026.242.1615 — feat(WP4): bring the resize gate into the corpus

## Summary

Brings **WP4's resize gate** into the corpus by advancing `layer-cstream-desktop` to
`v2026.242.1606`, which carries `pod-cstream v2026.242.1603` — the build pinning the streamer
revision with the runtime control socket and authoring the gate against it.

**The gate observes the compositor, not the streamer's own report.** Each resize is paired with a
`wl: hypr-monitors` observation, because the socket reply proves only that the *streamer* applied
new caps. The plan records the concrete hazard: Aquamarine snaps an unsatisfiable configure to
1280×720 **in silence** — so neither "no error" nor "the streamer said OK" is evidence that the
compositor followed.

```
resize 1600 900  ->  socket: OK resize 1600x896  ->  monitor: "width": 1600  "height": 896
resize 640 480   ->  socket: OK resize 640x480   ->  monitor: "width": 640   "height": 480
```

Both dimensions are asserted with their JSON keys. `"1600"` alone would match a coordinate or a
refresh rate; **896 is the rounded height** and can only appear if round-to-8 reached the
compositor rather than stopping at the capsfilter.

The bed goes from 62 checks to **65**.

## Two corrections this carries

**The plan's WP4 gate names a size that cannot apply.** It lists `1600×900`; 900 is not a multiple
of 8, so `Geometry::sanitised()` applies it as **896**. A gate asserting the requested value would
fail against correct behaviour. The gate asserts `1600x896`, with the reason inline in the bed so it
is not "corrected" back.

**`3840×2160` is deliberately not gated.** This bed runs rootless on a shared iGPU; a 4K reconfigure
is a materially different resource claim and has not been measured. A gate that has not been run is
not a gate. It belongs with `check-cstream-vm` (WP9b), where the GPU surface is declared rather than
borrowed — named here rather than silently dropped.
