# 2026.295.1047 — feat(bed): prove a containerd v4 config through egress validation (opencharly/charly#929)

## Summary

Adds the first assembled R10 bed that drives a config through the REAL `verb:egress`
validator, closing the containerd half of opencharly/charly#929.

`opencharly/plugin-egress#14` made `#ContainerdConfig` a
`#ContainerdConfigV2 | #ContainerdConfigV4` union, but no `disposable: true` bed
anywhere exercised `ValidateEgress` on that kind, so the change could only carry the
tier `analysed on a live system`. This bed is the runtime gate for that path.

| file | change |
|---|---|
| `candy/containerd-v4-egress/charly.yml` | new candy: installs `containerd` + `crictl` + `crun` + `krun`, ships the scratch fixture project, ADE-complete |
| `candy/containerd-v4-egress/fixture/` | self-contained generate-only project: a scratch box + the candy whose `config:` step carries the **structured pre-image** of the CONTAINERD.md §3.1 v4 config with `validate: containerd_config` |
| `charly.yml` | `containerd-v4-vm` (Arch cloud-image template, the same substrate decision `punktfunk-vm` records) and `check-containerd-v4-egress-vm` (the bed) |

The bed is the three-step shape, so it can FAIL without the v4 arm:

1. `v4-config-not-yet-accepted` — on the fresh guest, no version-4 config and no `crun` runtime handler.
2. `v4-config-validated-through-egress` — `charly box generate` over the fixture project IS the egress validation; the accepted pre-image is rendered to the TOML the daemon loads (no second copy of the values) and the rendered file is parsed back. On a v2-only schema this fails with `version: conflicting values 2 and 4`.
3. `v4-config-accepted-and-served` — the running daemon's `crictl info` lists the `crun` and `krun` runtime handlers, `containerd config dump` shows the CRI images plugin's `overlayfs` snapshotter, `ctr plugins ls` shows the snapshotter plugin as `ok`, and `ss -lx` shows the v4 `[plugins.'io.containerd.server.v1.grpc']` address (`/run/containerd-v4-egress/containerd.sock`) with the default gRPC socket absent.

The fixture candy also ships a runtime check (the fourth live step), so the bed reports
`4 passed, 0 skipped` — the add_candy plan IS collected into check-live, and a
build-scope check would have been counted as SKIP.

The v4 config deliberately carries the plugin-path gRPC and ttrpc keys rather than a
top-level `[grpc]` (which v4 ignores and which cost a host its system socket). The
daemon runs inside the disposable VM; the host's `/run/containerd/containerd.sock`
was recorded before and after (below).
