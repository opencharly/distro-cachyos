# 2026.243.0032 — feat(WP5): gate wl: type and wl: key-combo with observable side effects

## Summary

Gates `wl: type`, `wl: key` and `wl: key-combo` against the live nested Hyprland — the WP5 items the
plan listed as still open because they "need a mapped terminal + an observable side effect".

**One changed file:** `charly.yml` — 8 checks added to `check-cstream-pod`. No new candy, no pins,
no Go.

## Why each action is paired with an observation

`wl: type`, `wl: key` and `wl: key-combo` **all exit 0 even when nothing is delivered.** A verb that
dispatches into the void looks identical to one that works, which is precisely the failure a
keyboard gate exists to catch — and it is the same trap the existing `wl-focus-*` / `wl-minimize-*`
pairs already guard against, where asserting the dispatcher's exit code would have proved nothing.

**The observable is a real process, not a synthetic marker.** Typing `sleep 313` and pressing Return
starts one, and its existence proves three things at once that no single assertion could:

1. the keystrokes crossed the compositor,
2. they were delivered to the **focused** client (not merely to the seat), and
3. its shell executed them.

`ctrl+c` then kills it, which is the `key-combo` observation — and that leg **cannot pass vacuously**
because the preceding check proved the process was there to kill.

| id | action | observation |
|---|---|---|
| `wl-input-fixture` | spawn a dedicated `foot -T cstream-input` | it appears in `hyprctl -j clients` |
| `wl-input-focus` | `wl: focus initialtitle:cstream-input` | — |
| `wl-input-focus-observed` | — | it is the **active** window, so typing has a destination |
| `wl-type-command` | `wl: type "sleep 313"` | — |
| `wl-key-return` | `wl: key Return` | — |
| `wl-type-observed` | — | `pgrep -f 'sleep 313'` **finds** it |
| `wl-keycombo-interrupt` | `wl: key-combo ctrl+c` | — |
| `wl-keycombo-observed` | — | `pgrep` no longer finds it |

### A dedicated terminal, deliberately

The focus and close fixtures' windows are *targets* of dispatchers that move or destroy them.
Typing into one of those would race those gates and make both flaky, so this spawns its own window
and uses `initialtitle:` — the stable selector, because `foot` rewrites its live title from the
shell prompt within a second of mapping and every window then reports `@host:~`.
