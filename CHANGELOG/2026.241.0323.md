# 2026.241.0323 — fix: pin distro-arch v2026.241.0311 - clears the four plugin-mcp/plugin-record conflicts

## Summary

The `arch:` import pinned `distro-arch:v2026.236.0159`, whose candy refs still reach a
**pre-cutover charly**. A pre-cutover charly tree carries `candy/plugin-mcp` and
`candy/plugin-record` inline, so it registers as a second provider of both names and collides
with the standalone `opencharly/plugin-mcp` and `opencharly/plugin-record` repos:

```
remote candy name conflict: "plugin-mcp"    provided by both …/charly and …/plugin-mcp
remote candy name conflict: "plugin-mcp"    provided by both …/plugin-mcp and …/charly
remote candy name conflict: "plugin-record" provided by both …/charly and …/plugin-record
remote candy name conflict: "plugin-record" provided by both …/plugin-record and …/charly
```

These four have been blocking `check-selkies-labwc-pod` — `charly box build` validates the whole
project before building any box, so they abort the run before `selkies-labwc` is reached.

**Why the fix could not arrive until now.** `distro-arch` repaired its own refs in PRs #25 and
#28, but could not ship them: every `tag-on-merge` run in that repo ended in `startup_failure`, so
`main` sat four commits past its newest tag and no consumer could pin the fix. `distro-arch#29`
repaired the dispatcher, and the repo then produced **`v2026.241.0311`** — its first tag since
`v2026.236.0159`. That tag carries the charly refs at `v2026.240.0759`, which is post-cutover and
has no inline `plugin-mcp` / `plugin-record`.
