## Summary

**Successor of #169** (auto-closed by the review policy after five verdicts — a policy action, not a code finding).
ONE clean commit on a fresh branch off `origin/main`, carrying the final state of that work: the five checks, the
round trip in-container, the workflow's checkpoint name expanding, and the pin on the shipped candy tag.

`pod-comfyui` **v2026.319.0108** carries the fixes this cutover found: the application is cloned at the PINNED tag
into `/opt/comfyui`, all state lives in the volume via `--base-directory`, the dead `ltdrdata` Manager clone is gone
(`--enable-manager` replaces it), and the dependency set is **derived** from the tag's own `requirements.txt` —
including `comfy-angle`, whose absence a live start reports as `ModuleNotFoundError`, and `pyopengl`.

This PR does two things:

1. **moves the box pin** to that tag (`box/comfyui/charly.yml` → `pod-comfyui:v2026.319.0108`);
2. **makes the bed prove the contract instead of liveness.** `check-cachyos-comfyui-pod` previously asserted that
   the server answered, plus inherited baked checks. That assertion would have stayed **green through every defect
   this cutover found**, because none of them stopped the server from answering. It now runs five checks against the
   deployed pod:

   - the serving ComfyUI reports `"comfyui_version": "0.45.3"` from its own API (the pinned tag, not whatever
     `main` was on build day);
   - the application lives in the image (`/opt/comfyui/.charly-ref` matches, the start script is executable) and
     the volume holds **no** `main.py` — the app/state split;
   - the retired `ltdrdata` Manager checkout is **absent**, so it cannot creep back;
   - the state tree the start script seeds is complete inside the volume (`custom_nodes` included — its absence
     was a measured hard start failure);
   - **a real generation round trip**: `POST /prompt` with a 64×64 txt2img workflow, then poll `/history` for the
     SAME prompt id and require success.

Refs opencharly/distro-cachyos#167.
