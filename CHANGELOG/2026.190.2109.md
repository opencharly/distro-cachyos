# 2026.190.2109 — charly-cachyos is not a check bed: `disposable: true` removed

`charly-cachyos` is a `local:` deploy with `host: local`, `allow_root_tasks: true`, and
`allow_repo_changes: true`. It provisions **the operator's real workstation**. It also carried
`disposable: true`.

**That flag made it a roster bed, and a routine R10 gate provisioned the host.** A
`/verify-beds` run discovered it — the discover predicate is exactly *"a top-level entity
whose substrate node carries `disposable: true`"* — and ran `charly check run charly-cachyos`.
That spent **697 seconds** in `deploy-add`, installing `gstreamer`, `orc`, `pipewire`, `gtk4`,
`gtk4-layer-shell`, `appstream`, `libadwaita`, `ghostty`, `libva-utils` and more as root
(`/var/log/pacman.log`, 22:15), before dying in the chrome AUR builder:

```
charly: error: rpc error: code = Unknown desc = plugin-deploy-local:
  walk step "Builder" (candy=chrome): transferAndInstallPkgs: no package files to install
```

**The root cause was a conflated meaning.** The removed comment claimed the entity was
*"NOT a zero-side-effect test bed … so it stays a kind:deploy operator entry, not an check
bed"* while still setting `disposable: true` "so `charly update` is allowed for strict R10
verification". Both cannot hold. `disposable: true` is not merely "unattended destroy is
authorized" — it is the **sole definition of a check bed** (a check bed IS a deploy marked
`disposable: true`; there is no separate `check:` block — `/charly-check:check`). Setting the
flag makes an entity a roster bed by construction.

**The fix.** The flag is removed, and the comment now says why it must never return.

**Accepted consequence:** `charly update charly-cachyos` is no longer an unattended
destroy+rebuild. It is a hard-to-reverse action on a non-disposable resource and requires
operator confirmation, like every other such resource (CLAUDE.md "Disposable-Only Autonomy").

**Verification.** `charly -C box/cachyos box validate` — exit 0, zero warnings. The discover
predicate no longer yields `charly-cachyos` (18 disposable entities remain in this repo; it is
not among them). `validateCheckBeds` enumerates `uf.CheckBeds()` and requires `IsDisposable()`
— validate passing rather than erroring confirms the entity is no longer enumerated as a bed.

`charly check run charly-cachyos` was **deliberately not executed** to demonstrate the refusal:
that command is the hazard this cutover removes, and running it against the host to prove it is
now safe would be the same mistake in miniature.
