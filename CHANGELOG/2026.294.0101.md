# 2026.294.0101 — fix(skills): complete the three cachyos skill carriers with real candy nodes and strip the duplicated inline bodies (sdk#434)

## Summary

`distro-cachyos` already had the carrier **directories** the operator ruling points at, and they
held the eleven `skill:` nodes — but **none of them declared a `candy:` node**, so they were not
candies at all: `candy: [cachyos-os-skills]` failed with `candy "cachyos-os-skills" not found`.
That is the gap the ruling measured, and this PR **completes the pattern** rather than inventing a
scheme: each of the three carriers becomes a real candy, each image that owns one of its skills
composes it, and the prose moves into a file beside the carrier.

Two defects are fixed at once, both present on `main`:

1. **Nine nodes named IMAGES as their owner** — `versa`, the four OS images (`cachyos`,
   `cachyos-pacstrap`, `cachyos-pacstrap-builder`, `githubrunner`) and the four `selkies-*`
   desktops. A `candy:` node carrying `base:`/`from:` has no source directory, so its prose can
   never be read; and `CollectSkills` keeps only nodes whose `owner:` is in the composed candy
   chain — an image is never in it. Those nine were **silently absent from every
   `ai.opencharly.skill` label**.
2. **All eleven nodes still carried an inline `content:` block that duplicated the root
   `.agents/skills/` file.** `#132` landed the root files without stripping the bodies, so `main`
   carries **two copies of the same prose** — the dual-read state R5 forbids.

### Why this creates/repairs a carrier candy

The operator ruling on `opencharly/sdk#434` (`OPERATOR RULING, EXTENDED`) authorises exactly this,
and it was measured twice:

- **16 of 17 image-owned nodes in this programme have no local package candy at all**, and five of
  those images compose **zero** candies — so "re-home to a candy the image already composes" is
  impossible, not merely awkward.
- **`distro-cachyos` is itself the precedent the ruling cites.** Its `candy/cachyos-app-skills`,
  `candy/cachyos-os-skills` and `candy/cachyos-selkies-skills` are the shape to copy; their single
  defect was the missing `candy:` node, which is the whole of what this PR adds to them.
- Rejected: ownership by a semantically wrong candy (`cachyos-base-check`), and a repo-root
  fallback (`sdk#528` option B, which the ruling rejected because it decides the layout question
  for ~430 repos).
