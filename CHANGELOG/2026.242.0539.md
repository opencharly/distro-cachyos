# 2026.242.0539 — feat: the cstream box and its pod bed

## Summary

Give cstream its home in the distro: a box, a witness box, a bed fixture, and the R10 bed.

| path | role |
|---|---|
| `box/cstream` | the streamed Hyprland desktop on the CachyOS base — one member, `layer-cstream-desktop:v2026.242.0422`, which composes the transport spine with the nested compositor |
| `box/cstream-check` | the **witness** box: `cstream` plus the login fixture, and nothing else |
| `candy/cstream-probe-account` | the bed fixture — gives the container's own runtime account a known password |
| `charly.yml` | `check-cstream-pod`, the bed |

**Why two boxes.** The login gate needs an account whose password is known. Composing the fixture
into `box/cstream` would bake that password into the box every consumer builds, so the fixture
lives in a witness box the bed targets and `box/cstream` stays credential-free.

**Why the fixture is shaped the way it is** — both halves are forced by measured behaviour, and
neither is obvious:

- It sets the password at **build** time. A rootless pod execs as uid 1000 with an empty
  capability set, so `useradd` at runtime fails with *"cannot lock /etc/passwd"*.
- It targets the container's **own** account. `pam_unix` delegates to the setuid helper
  `unix_chkpwd` whenever euid ≠ 0, and that helper only verifies the **calling** user's own
  account — so authenticating any other account fails with *"Authentication service cannot
  retrieve authentication info"* **regardless of the password**. That would make *both* legs of
  the login gate fail, and a reject-leg passing for the wrong reason is worse than no gate.

**Why the bed's gates are shaped the way they are.** A service check proves a process is up —
measured, charly's own `service:` verb reports PASS for a supervisord program parked in FATAL
(`opencharly/charly#456`). A screenshot proves the compositor draws, not that the encoder and
transport carry the pixels. And "the frame is not uniform" passes on a wallpaper, so a frozen
pipeline serving one static frame forever satisfies it. So the streaming gate compares frames
pulled **through the pipeline** before and after a real client window maps.

- **R1 — RCA every anomaly.** The one `box validate` warning was traced to a box outside this diff
  by re-measuring against a clean clone of `main`, rather than being attributed or ignored.
- **R2 — nothing parked.** The login **broker** is not gated here and the reason is structural,
