# 2026.290.1628 — fix(cachyos): give the eleven skill routing nodes the description and content the schema requires

## Summary

**This fixes a repo-wide blocker, not a cosmetic validation gap.** `candy/cachyos-{app,os,selkies}-skills` carry eleven thin skill routing nodes (`name`/`family`/`owner`, no body). `#SkillInput` requires **both** `description` and `content` to be non-empty, and the failure is not confined to `validate` — **project resolution itself fails on the first node**, so *no bed in `distro-cachyos` could run at all*:

```
charly: error: command "check": InvokeProvider build:project op=resolve: build project:
  /home/atrawog/dc-pins/candy/cachyos-app-skills: node "charly-cachyos-skill":
```

That was found while trying to run an R10 bed for another change in this repo; it is the reason that bed could not even start.

Both required fields are filled for all eleven nodes, sourced from each node's own **`.agents/skills/<name>/SKILL.md`** — which this repo's `AGENTS.md` names as the source of record for the prose — so **no text is invented**: the frontmatter `description:` becomes the node's `description:` (as a block scalar), and the body after the closing `---` becomes the node's `content:`.

Files touched: `candy/cachyos-app-skills` (3 nodes), `candy/cachyos-os-skills` (4), `candy/cachyos-selkies-skills` (4).
