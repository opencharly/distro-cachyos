# 2026.241.0033 — fix: reference charly's candies individually - the repo root is not a candy

## Summary

`candy/charly-marketplace` referenced the charly **repo root**:

```yaml
- '@github.com/opencharly/charly:v2026.240.2219'
```

A repo root is not a candy node, so it never resolved. Two validation errors resulted, and none
of charly's `skill:`/`hook:` entities reached the corpus this candy exists to collect.

Replaced with the nine charly candies that actually own `skill:`/`hook:` entities. The list is
**enumerated, not guessed** — a grep of charly's candy tree for those keys returns exactly these
nine and nothing else:

```
$ for d in candy/*/; do grep -qE '^\s{4}(skill|hook):' "$d/charly.yml" && basename "$d"; done
charly            charly-image      charly-internals-extra
charly-build      charly-immich     charly-kubernetes
charly-check      charly-internals  charly-mcp
```

**Scope, stated plainly:** this fixes the two `unknown candy` errors and nothing else. The four
`plugin-mcp`/`plugin-record` conflicts and the three `openclaw` `socat` errors are **not**
affected — I measured that specifically, because I had hypothesised they were downstream of this
partial charly load. They are not. They remain open members of the post-cutover plugin-candy pin
reconciliation batch.

**Do not "simplify" this by deleting `candy/charly-marketplace`.** Measured: removal is strictly
worse — `pixi` and `rust` then fail to resolve for `selkies-labwc` and `openclaw-full`. The refs
list is what brings the standalone candy repos into scan range.

## How tested

Two-way control on this host, charly built from `charly@main`, no local overrides, both legs run
from a committed tree (R10):

```
$ git checkout main && charly box validate | grep -cE 'conflict|unknown candy|missing "socat"'
9
$ charly box validate | grep -E 'unknown candy "github.com/opencharly/charly"'
   candy "github.com/opencharly/charly/candy/charly-marketplace" candy: unknown candy "github.com/opencharly/charly"
   candy "charly-marketplace" candy: unknown candy "github.com/opencharly/charly"

$ git checkout fix/charly-marketplace-repo-root-ref   # commit aa69f37
$ charly box validate | grep -cE 'conflict|unknown candy|missing "socat"'
7
$ charly box validate | grep -cE 'unknown candy "github.com/opencharly/charly"'
0
```

Both error lines gone; the delta is exactly 2; the other 7 are unchanged.
