# 2026.322.1045 — fix(skills): give cachyos-coder-tools the frontmatter its entity requires

Agent: charly (session lead, opencharly umbrella)

## Summary

`.agents/skills/cachyos-coder-tools/SKILL.md` had **no YAML frontmatter** while its entity (`candy/cachyos-app-skills/charly.yml:59-65`, node `cachyos-coder-tools-skill`) carries an inline `description:`. The corpus generator compares the two and refuses the entire corpus on a disagreement, so `opencharly/marketplace`'s scheduled `refresh` has been **red every day since 2026-11-12** (six consecutive runs, `44096889064` being the latest) with:

```
charly marketplace: skill "cachyos-coder-tools": the node's inline `description:` and its file's frontmatter disagree
```

This adds the frontmatter in the shape every sibling already uses (`---` / `name:` / `description: |-` / `---`, 2-space indent). The description is **generated from the entity** by a script and then re-parsed and compared, so the pair cannot drift by a character — the failure mode this PR is fixing.

Nothing else in the repo moves: one file, six added lines.

## How tested

The generator's own comparison, run repo-wide over every `skill:` node in `candy/**/charly.yml` against its `.agents/skills/<name>/SKILL.md` — on the **same tree at the same commit**, once with the change stashed and once with it applied:

```
$ git -C <worktree> stash          # the pristine tree
  12 entity/file pairs agree
    BAD: cachyos-coder-tools: NO FRONTMATTER

$ git -C <worktree> stash pop      # the change applied
  13 entity/file pairs agree       # no BAD line
```

The comparison fails without the change and passes with it, which is the property the coverage has to have. The repo's own structural gate is green on the committed tree:

```
$ ./charly/bin/charly -C <worktree> box validate
charly box validate: OK — checked 331 candies, 44 boxes, 49 deploys, 6 distros, 7 builders; 0 warnings, 0 errors
```

End-to-end proof — the scheduled refresh going green and regenerating the corpus — cannot be run from here: the generator's root is the `marketplace` repo's refs list, which pins this repo at a **tag**, so a local run cannot see this branch. The first scheduled run after merge is that proof, and it is the same run that will finally publish the immich retirement's corpus consequence.
