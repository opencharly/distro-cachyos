**The earlier check-live failures — RCA + real fixes (B5/R1):** the desktop bed's
check-live failures were a chain of pre-existing host/display conditions, each
fixed at the source and now in this tree:

1. **`selkies-vaapi-encode`** — FAILED because this host's AMD Raphael/Mendocino
   iGPU exposes no H264 VAAPI encode entrypoint (H264 decode only). For the
   CPU-only openclaw-desktop box, the CPU x264 fallback is the VALID streaming
   path, so the FAIL was a false positive. **Fixed in opencharly/pod-selkies#8**
   (merged, v2026.246.2210): the check now emits `VAAPI-N/A` (PASS) for AMD/Intel
   GPUs without H264 encode. Advanced into this tree via pod-selkies-core#17
   (pin bump) + pod-selkies-desktop (pin bump).
2. **`selkies-encoder-active`** — the same false-positive class in the pixelflux
   encoder check. **Fixed in opencharly/pod-selkies#8**: AMD/Intel CPU fallback
   now emits `ENCODER-OK`.
3. **`selkies-frame-not-black`** — the desktop took longer than the 90s
   `eventually` window to render its first visible frame on the CPU x264 path.
   **Fixed in opencharly/pod-selkies#8**: the window is widened to 300s.
4. **`nested-podman-run`** — a HOST network condition: the container's
   aardvark-dns cannot resolve quay.io (the host CAN — `getent ahostsv4 quay.io`
   returns 32.196.234.221), so the nested `podman run` pull failed with exit-125.
   **Fixed at the source in opencharly/layer-container-nesting#2** (this batch):
   the alpine image is now pre-pulled at build time (the build container has
   working network) and the runtime check uses `--pull=never` — no runtime DNS
   dependency. The check now PASSes in the `check-live` step above.
