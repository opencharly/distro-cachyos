# 2026.328.0900 — fix(pins): advance layer-charly to the pixi HOME/PIXI_HOME release

## Summary

Five `layer-charly:v2026.327.0856` pins in `charly.yml` move to **`v2026.328.0806`** — the release
whose manifest pins `plugin-builder-pixi` at `v2026.327.1705`. That builder sets `HOME` and
`PIXI_HOME` in the pixi stage it emits, so a pixi environment lands inside the box home again; the
previous release set neither and the environment landed outside it, which is why `<home>/.pixi` was
missing from every image built through the Arch builder leg.

This is the consumer leg of opencharly/layer-charly#26 (merged, tagged `v2026.328.0806`). The pin
chain: `charly/charly.yml` (the binary's builder pins) → `layer-charly` (the layer baked into the
builder image) → **this repo** → the ComfyUI beds.

| File | Change |
|---|---|
| `charly.yml` | five `layer-charly:v2026.327.0856` → `v2026.328.0806` (lines 192, 220, 843, 2276, 2368) |

## How tested

**The changed path proved its own effect on this tree, with no override:**

```
$ charly box generate comfyui-cdi                     # EXIT=0
plugin github.com/opencharly/plugin-builder-pixi/candy/plugin-builder-pixi: …
  source <cache>/repos/github.com/opencharly/plugin-builder-pixi@v2026.327.1705.view.c51cf86ad9b43421/candy/plugin-builder-pixi

$ grep -m1 'ENV HOME=.*PIXI_HOME' .build/comfyui-cdi/Containerfile
ENV HOME=/home/user PIXI_HOME=/home/user/.pixi
$ grep -c PIXI_HOME .build/comfyui-cdi/Containerfile
2
```

Before the change, the same command on the same tree served `plugin-builder-pixi@v2026.326.2258` and
`grep -c PIXI_HOME` returned `0`.

**The EFFECT is proven on a fresh rebuild, not only the generated stage.** Same tree, same binary:

```
$ charly box build comfyui-cdi                        # fresh build, EXIT=0
--- Building podcdi.pod-cdi-layer-cuda-layer-supervisord-2 ---
--- comfyui-cdi: ghcr.io/opencharly/arch-builder:2026.328.0834 from the charly image store ---
--- Building comfyui-cdi ---

$ charly shell comfyui-cdi -c 'ls -d /home/user/.pixi && ls /home/user/.pixi | head -3 && test -d /home/user/.pixi && echo PIXI_HOME_PRESENT'
/home/user/.pixi
envs
PIXI_HOME_PRESENT
```

`<home>/.pixi` now exists in the built image, which is precisely what every `<home>/.pixi` check in the
opencharly/pod-comfyui candies asserts and what the previous release made impossible.

**The composition link** (the non-blocking note): the five advanced pins belong to
`check-cachyos-vm`, `check-cachyos-mcp-vm`, `check-cachyos-gpu-vm`, `cachyos-gpu` and
`charly-cachyos-app`. `comfyui-cdi` composes none of them — the pin reaches it because the remote-ref
FETCH SET is project-wide: a layer any box in the project composes contributes its `candy:` pins to
one deduped set, and the builder plugin is vendored at that ref for every box in the project. That is
not an assertion about intent but a measurement: bumping only those five pins moved `comfyui-cdi`'s
served builder ref from `v2026.326.2258` to `v2026.327.1705`, before and after on the same tree.
