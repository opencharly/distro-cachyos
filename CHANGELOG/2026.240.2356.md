## What remains, and one non-obvious finding

Nine validation errors remain, all members of the named **post-cutover plugin-candy pin
reconciliation batch**:

```
remote candy name conflict: "plugin-mcp"    provided by both .../charly and .../plugin-mcp
remote candy name conflict: "plugin-record" provided by both .../charly and .../plugin-record
box "openclaw" / "openclaw-full" / "openclaw-desktop": port_relay candies but missing "socat"
candy "charly-marketplace" candy: unknown candy "github.com/opencharly/charly"
```

**The non-obvious part, recorded so nobody repeats my experiment:** `candy/charly-marketplace`
looks like the culprit, since it pins the whole `charly` repo, which is where the second
provenance comes from. **Removing it makes things strictly worse:**

```
$ rm -rf candy/charly-marketplace && charly box validate
box "selkies-labwc":  candy resolution error: unknown candy "pixi"
box "openclaw-full":  candy resolution error: unknown candy "rust"
```

It is load-bearing — it is the refs list that brings the standalone candy repos into scan range
so bare names elsewhere resolve at all. Neither `plugin-mcp` nor `plugin-record` is referenced
anywhere in this repo directly (grep returns nothing), so both provenances are **transitive** and
the fix belongs in whichever pinned candy double-provides them, not here. I am not guessing at
that inside a pin bump.
