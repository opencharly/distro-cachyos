## The four mechanisms, each measured on a live deploy

| # | mechanism | how it was measured | fix |
|---|---|---|---|
| 1 | a member nested **inside** `pod:` is in-substrate, so nothing brings it up beside the parent | `bring-up-members` PASSed in 77 ms with no member container; `deploy_members.go:106` DOES config+start+wait a container member | member is a **sibling of the kind key** — deploy count 44 → **45** |
| 2 | `COMFYUI_BASE_URL: http://${HOST:comfyui-peer}:8188` | `printenv` in the pod returned the **literal** — `${HOST:…}` is a *plan-step* substitution, not a deploy-env one | the concrete `http://charly-comfyui-peer:8188` |
| 3 | the deploy never named the engine | Open WebUI defaults `IMAGE_GENERATION_ENGINE` to `openai`, so it POSTed to api.openai.com with an empty key and came back `[ERROR: Unauthorized]` *… but* | `IMAGE_GENERATION_ENGINE: comfyui` stated by the deploy — the image's `env_provide` does not reach a deployment |
| 4 | node 4 of Open WebUI's default workflow asks for `"ckpt_name": "model.safetensors"` | the **primary's own log**: `ClientResponseError: 400, message='Bad Request', url='http://charly-comfyui-peer:8188/prompt'`, with the member's queue empty | a **STATIC** node entry rewrites node 4 to the checkpoint the member fetched |

**Mechanism 4 is the one that ended five runs of guessing**, and the lesson is in the ledger: a probe that *bypasses*
the subject (`direct=200`, a prompt POSTed straight at the member) proves the transport and never the payload. The
answer was in the server's log, not in its response body.

The static entry is deliberate: a `type: model` node substitutes `IMAGE_GENERATION_MODEL`, which is unset and is
therefore the **empty string** — the empty `ckpt_name` that made an earlier attempt fail differently.
